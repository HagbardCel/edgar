# Target entities, identity, and ownership

**Status:** recommended logical model. Names below identify implementation destinations, not a requirement to create every optional table immediately. M1–M4 structures are committed recommendations within this package; M5 additions require their stated evidence gates. Existing and new rows never redefine raw evidence.

## Identity vocabulary

- **QName:** exact namespace URI and local name. Reuse `source.concept` and its existing deterministic UUID. Keep the two textual components authoritative; do not add a second `qname` identity table. Datatype/unit/resource names can be expanded-QName values without pretending all are item concepts.
- **ReportRef:** accession plus the full report input (ordered entrypoint URI list and target), with the existing `report_key` as lookup aid.
- **BundleRef:** relative descriptor path, descriptor-file SHA-256, and its saved manifest content. The path identifies a stored bundle; the digest checks the descriptor bytes. This is not a new domain-level bundle equality algorithm and does not replace `payload_hash`.
- **OccurrenceRef:** BundleRef + ReportRef + artifact path/hash + deterministic element locator. Include the extraction/source-order ordinal as diagnostic/disambiguation metadata, not as a portable identity by itself. Inline target/report membership distinguishes one element's report association. If the adapter cannot distinguish relevant occurrences, fail rather than collapse them.
- **ContractRef:** metric key plus semantic definition hash and exact contract content.
- **AssertionRef:** named integer revision within the preserved logical ledger, plus immutable claim/evidence content in portable exports. Normal restore preserves revision IDs and predecessor relationships. Cross-ledger merges require explicit ID remapping; they are not silently supported.

These are typed value objects/JSON schemas, not new identifier microservices or tables. Local foreign keys remain useful for joins.

## Evidence and catalog

| Structure | Purpose; grain and identity | Relationships | Durability / truth / regeneration |
|---|---|---|---|
| CAS artifact | Exact bytes; SHA-256 | Referenced by bundle inventory | Durable immutable source truth; never reconstructed from SQL |
| FilingBundle | Complete acquisition/replay package; BundleRef | Filing, artifacts, report inputs, canonical URI/alias bindings | Durable immutable source truth; preserve original descriptor and all referenced objects |
| Acquisition receipt | Retrieval observations; one attempt | Bundle/artifact refs, retrieval times, failures | Durable operational evidence; not semantic identity; success does not imply extraction success |
| `source.issuer` | Registrant catalog; CIK | Many filings | Rebuildable catalog; source metadata authority; name is descriptive, not historical security identity |
| `source.filing` | Submission; accession | Registrant, documents, reports | Durable catalog identity, rebuildable from manifests; facts never merge across accessions |
| `source.document` | Filing-associated artifact; filing/path | SHA, URI, blocks and extraction locators | Rebuildable inventory mirror; verified bytes remain authority |
| `source.xbrl_report` | Current interpreted report; filing/report key | Full input + extraction receipt, children | Replaceable per filing; Arelle/parser versions and configuration recorded as metadata |
| Extraction receipt on report | Exact inputs/config used, embedded JSON plus BundleRef | Descriptor, policy/config, code/lock identity, engine version | Current receipt regenerable; copied into every durable evidence/publication that relies on it |
| `source.concept` | Shared exact QName | Report declarations and assertions | Regenerable identity but no GC while referenced by knowledge; never global declaration properties |

Retain one live catalog inventory per filing for now. Reacquisition with different verified bytes at the same filing/path must fail catalog compatibility; preserve both filesystem bundles for investigation. Do not overwrite existing verified objects or reset the catalog automatically. Supporting multiple live acquisition inventories is deferred until a demonstrated corrected-resource case requires it.

Persist BundleRef/extraction configuration before a report becomes eligible for publication. Old rows without a receipt remain inspectable but need verified offline re-extraction. A filesystem search that finds a plausible matching payload is not proof of the original load inputs.

## Native XBRL and text structures

All structures below are replaceable current extraction evidence, generated by the versioned adapter/parser from the pinned bundle. They are not independently authored knowledge. Preserve old publications through portable snapshots, not FKs to these replaceable rows.

| Structure | Grain / identity | Important content and relationships | Target change |
|---|---|---|---|
| Concept declaration | Effective declaration per report/QName | Datatype, period type, balance, abstract/nillable, substitution group, source declaration locator | Add typed-domain reference/locator and needed resolved base-type classification, derived by Arelle; keep raw declaration authoritative |
| Context | Report + source context ID | Filed entity scheme/identifier, instant/duration/forever, original period lexicals, optional aware timestamps, locator | Retain; conflicting duplicate context IDs in IXDS must be detected, not overwritten |
| Context dimension | Filed occurrence under context | Dimension/member QNames or namespace-complete typed XML; segment/scenario; locator | Retain row multiplicity; no new uniqueness constraint that hides invalid duplicates |
| Opaque context content | Ordered non-dimensional segment/scenario fragments per context | XML + source locator + explicit unhandled-semantic flag | M1 adds preservation; inspection allowed, analytical qualification blocked until supported |
| Unit | Report + source unit ID | Unit locator, measures | Retain; collision guard like contexts |
| Unit measure | Unit + numerator/denominator + ordinal | Expanded QName and multiplicity | Retain; comparison uses a measure multiset, not display spelling/order |
| Fact occurrence | Report + source order; portable OccurrenceRef | Concept, context, nullable unit, raw/resolved value, value status, nil, accuracy, Inline attributes, language, continuation refs | Retain; do not make an economic uniqueness constraint |
| Role declaration | Report + URI + declaration locator | Definition, `usedOn`, artifact | ADD; URI alone is not declaration occurrence identity |
| Arcrole declaration | Report + URI + declaration locator | Definition, `usedOn`, `cyclesAllowed`, artifact | ADD |
| Effective relationship | Report + source order | Source/target declaration in same report; full base-set key, order/weight/preferred label/targetRole, dimensional attributes, arc locator | ADD link QName and arc QName; preserve exact network key |
| Concept label association | Report + source order | Concept, full network key, language, resource role/text, arc and resource locators | Retain; carry link/arc QNames where applicable |
| Concept reference association | Report + source order | Concept, full network key, resource role, ordered QName/XML reference parts, both locators | Retain; no flattening to a single documentation string |
| Footnote resource | Report + resource locator | Language/role, text/XML, source artifact | ADD for supported fact-footnote associations |
| Fact-footnote association | Effective association occurrence per report | Fact OccurrenceRef/live FK, footnote ref, link role/arcrole and link/arc QNames, arc/Inline relationship locator | ADD separately from concept-to-concept edges; continuation is not a footnote |
| Extraction issue | Current diagnostic occurrence/group | Filing/report/document/locator, code/severity, diagnostic count/details | Retain; add explicit capability omissions and upstream fact inventory counts |
| Document block | Document + ordinal | DOM type, substantive text, source location, parser version | Retain |
| Filing section | Document + section key | Block range, method/confidence | Retain; parser claim, not filing-authored metadata |

Effective networks can be queried by `(report, arcrole URI, link-role URI, link QName, arc QName)` without a separate network table. Role definitions and `targetRole` traversal make network inspection useful. Presentation position is evidence; a fact does not have a uniquely filed “statement membership” column. A concept may appear in several networks.

Enforce same-report integrity: fact context/unit and concept declaration belong to its report; relationship endpoints, dimensions and members have declarations in that report where XBRL requires them. Use named composite constraints where appropriate and pre-persist validation for references encoded in JSON. A global concept FK alone does not establish declaration provenance. M1 tests determine any existing rows requiring rebuild before constraint validation.

Do not promise complete raw XLink or XML Schema persistence. Raw bytes preserve other declarations/arcs; Arelle replays them. Supported capabilities and exclusions accompany inspection and publication. Tuples and fractional facts remain explicitly unsupported until an actual in-scope fixture demands them.

## Semantic knowledge

| Structure | Purpose / grain / identity | Relationships | Durability / authority / regeneration |
|---|---|---|---|
| `registry/metrics.yml` | Current governed measurement contracts; metric key | References reviewed documentation; defines current meaning | Durable Git authority; semantic edits change definition hash |
| `registry.canonical_metric` | Current mirror; metric key | Points to current definition hash | Regenerable; YAML remains sole authoring authority |
| `registry.metric_definition` | Exact historical contract snapshot; `(key, definition_hash)` | Referenced by assertions/publications; includes hash inputs and a source Git ref when known | Immutable retained mirror of Git-authored meaning; not a second authoring surface; restore from retained YAML history/export |
| `registry.mapping_assertion` | Immutable decision revision of an immutable claim | Source QName, ContractRef, scope/conditions, predecessor, correction link, evidence | Durable DB authority; not regenerable from filings |
| Mapping evidence | Bounded structured packet within a revision | Typed source pins, extracts, observations, opposing evidence, generation/review provenance | Durable part of decision; content can be verified but human rationale cannot be regenerated |
| `registry.filing_relation` (M4) | Evidence-backed relation revision between accessions | `amends`, rationale/source pins, acceptance history | Durable if reviewed; directly sourced evidence included; never implies filing-wide financial replacement |

Keep mapping status succession as the existing linear immutable chain. New semantic claim content creates a new root; an explicit `replaces_root_id` links a correction without changing the old claim. Add a nullable `conditions` object for newly reviewed roots and copy it unchanged into their successors. Historic rows retain NULL conditions and their exact original content. The new publication API treats missing structured conditions/contract snapshots as `legacy_review_required`; existing audit commands continue to explain them under the original interval semantics. This is historical decoding, not two live mapping authorities.

Metric snapshots store semantic content keyed by the existing hash contract. Name-only display changes can update the current mirror without rewriting the economic snapshot; publications also retain the display name they emitted. Adding economic fields requires an explicit hash-contract change and re-review of affected mappings, never reinterpretation of an old hash. Legacy hashes whose content cannot be recovered remain historical unresolved references and cannot be used for publication.

Immutable knowledge must survive direct database mistakes as well as service convention. Use INSERT/SELECT privileges for the application ledger writer plus UPDATE/DELETE rejection triggers on history tables; migrations run as the owner. Preserve all predecessor and claim-copy constraints. Semantic acceptance/correction transactions lock relevant concept/contract rows in a documented common order, including registry sync, and recheck the candidate/definition after acquiring locks. Database enforcement supplements, rather than replaces, the service's economic checks.

## Derived queries and publications

| Structure | Purpose / grain / identity | Relationships | Durability / truth / regeneration |
|---|---|---|---|
| ConceptEvidence | One requested QName and report/corpus scope | Declarations, networks, facts, previous decisions | Query DTO; regenerable; accepted evidence snapshots retain the relied-on subset |
| MappingApplication | Fact occurrence × evaluated relevant assertion | Condition outcomes, target contract, retained source aspects | Query DTO/SQL view; regenerable, no durable affected-fact arrays |
| FinancialRequest | Exact requested observation slots and named policy/cutoffs | Corpus, ContractRefs, entity/slice/unit/period | Ephemeral query; immutable when included in export manifest |
| ObservationCandidate | Qualified support group within a filing/report and slot | Every supporting occurrence, exact assertions, checks | Query DTO; regenerable; no persisted candidate lifecycle |
| FinancialResult | One requested slot under a query policy | Selected value/support or explicit missing/conflict state | Ephemeral unless exported; snapshots retain its exact meaning |
| Publication directory | One exported request/result set | Manifest + results + lineage + exact semantic snapshots + hashes | Durable immutable published artifact; inputs can regenerate equivalent content but original is retained |
| Publication withdrawal notice | One correction/withdrawal event | Publication digest/path, reason, bad decision revision, replacement publication if any | Durable append-only notice outside original bytes |

Suggested publication layout is `manifest.json`, `results.jsonl` (and optional CSV), `lineage.jsonl`, and `knowledge.json`. Use JSON Decimal strings, never float conversion. Each result has a deterministic row key within that publication and joins to lineage by that key. Long-form output is the authoritative export; a wide statement is a presentation of those rows.

Manifest content: request/corpus inventory, all cutoffs and modes, exact definition and decision revisions, extraction receipts, input hashes, code revision plus dirty-tree patch if applicable, dependency lockfile identity/content, output hashes, generation timestamp, quality summary. Require a clean or explicitly captured implementation tree for reproducible publication. Operational timing belongs in the manifest but does not alter the economic observation key.

Lineage snapshots include source aspect/value/accuracy state, all co-support occurrences, declaration and mapping evidence pins, and selection reasons. Excluded alternatives are represented by bounded summaries plus a reproducible diagnostic query and the pinned corpus; cases whose resolution relied on particular exclusions pin those exclusions too. No snapshot needs a giant list of every fact a reusable mapping might ever affect.

Publication lookup initially reads manifests from an explicit local export directory. Defer a publication catalog table until listing/dependency lookup is measurably expensive. Restore must verify all hashes and demonstrate an old publication still explains after a source rebuild and a semantic revocation.

## Later structures: decided boundaries, deferred implementation

| Structure | Required grain if introduced | Trigger |
|---|---|---|
| Official taxonomy package index | Package/version/artifact digest + scoped declarations/edges; reuse QName identities | Repeated evidence inspection needs material absent from filing DTS |
| Canonical dimension/member assertions | Reviewed source-axis/member-pattern → canonical qualifier under scope | Two issuers' slices need defensible comparison |
| Aspect transformation | One reviewed expression with explicit input/output aspects and residual dimensions | Proven concept-dimensional equivalence cannot be expressed as a preserving mapping |
| Formula definition | Contract/version + executable formula + input contracts/unit rules | A named derived metric or explicit Q4/YTD subtraction product is requested |
| Derived observation | Output slot + formula + complete input observation refs | Formula has fixtures, basis compatibility, and availability rules |
| Canonical hierarchy | Reviewed directed contract relationship | Actual navigation or semantic query needs it; never a hidden aggregation rule |
| AI proposal artifact | One invocation: input packet hash, prompt/schema version, model/parameters, output/failure | Candidate generation begins; publication does not depend on model execution |

These do not yet justify empty schemas, plugin frameworks, entity-attribute-value tables, or universal graph node types.
